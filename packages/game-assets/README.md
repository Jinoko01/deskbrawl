# DeskBrawl 픽셀 에셋 · v2 (단순화)

캐릭터 8종의 의상·색상·컨셉을 유지하면서, 사용자가 업로드한 작은 캐릭터 예시의 단순한 표현 수준으로 다시 그린 에셋이다. 큰 픽셀 덩어리, 굵은 검은 외곽선, 점눈, 짧은 팔다리를 사용하고 머리카락·얼굴·옷의 세부 묘사를 줄였다. 장난감 무기·돌·이펙트도 같은 방향으로 단순화했다.

현재 미리보기와 메타데이터 생성 도구는 `*-v2.png` / `*-v2.json`을 사용한다. 접미사가 없는 기존 PNG와 JSON은 비교용 v1 원본으로 보존한다. 캐릭터 ID와 애니메이션 키는 그대로 유지한다.

이 폴더는 이미지와 애니메이션 메타데이터를 제공한다. 8종 캐릭터는 앱의 [`characters.ts`](../../apps/desktop/src/game/characters.ts)에 연결되어 있으며, 선택 UI·로컬 선택 저장·방 내 프로필 동기화는 `apps/desktop`과 서버가 담당한다. 능력치나 무기별 효과를 새 게임 규칙으로 정의하지 않는다.

## 먼저 보기

[`preview.html`](preview.html)은 별도 설치나 서버 없이 열 수 있도록 구성했다. 기본 표시 크기는 64px이며 8종의 대기·걷기·공격·투척·피격을 동시에 살펴볼 수 있다. 표시 크기, 밝은/어두운 배경, 일시 정지, 다음 프레임을 지원한다. 운영체제의 동작 줄이기 설정에서는 정지 상태로 시작한다.

- `validation.json`: 프레임별 비어 있지 않은 픽셀, 투명 픽셀, 셀 경계 침범 검사 결과.
- `PROMPTS-v2.md`: 이번 단순화에 사용한 내장 이미지 생성 도구와 최종 프롬프트 기록.
- `PROMPTS.md`: 기존 v1 생성 프롬프트.

PNG 원본은 RGBA 투명 배경이며, 배경·바닥·그림자가 시트에 합성되어 있지 않다. 이미지 생성 도구가 반환한 실제 해상도를 atlas에 기록한다. 프롬프트의 1024×1024 요청값을 좌표로 가정하면 안 된다.

## 애니메이션 계약

인덱스는 0부터 시작하고, 시트의 왼쪽 위에서 가로 우선으로 진행한다.

| 키 | 프레임 인덱스 | 미리보기 프레임 간격 | 게임에서의 재생 의도 |
| --- | --- | --- | --- |
| `idle` | 0, 1, 2, 3 | 220 ms | 반복 |
| `walk` | 4, 5, 6, 7 | 120 ms | 이동 중 반복 |
| `melee` | 8, 9, 10, 11 | 100 ms | 한 번 |
| `throw` | 12, 13 | 150 ms | 한 번, 돌은 별도 표시 |
| `hit` | 14, 15 | 220 ms | 피격 반응 |

위 시간은 **에셋 감상용 값**이다. 공격 쿨다운·명중 시점·기절 지속 시간은 서버 상태와 명세를 따른다. 모션 재생으로 명중이나 기절 종료를 판정하지 않는다. 사망·제거 애니메이션은 없다.

이펙트 atlas의 키는 `swoosh`, `impact`, `stun`, `dust`다. `stun`은 서버가 기절 상태를 해제할 때까지 반복할 수 있고, 나머지는 단발 표현으로 사용한다. 돌 atlas의 회전 키는 `stone-gray`, `stone-brown`이다.

무기 프레임 키:

```text
squeaky-hammer  foam-baton    practice-sword  rubber-chicken
foam-glove     fly-swatter   paper-roll      soft-mallet
```

## PixiJS 연결 시

JSON은 `frames`, `animations`, `meta.image`를 가진 sprite atlas 형식이다. PNG와 JSON을 **같은 디렉토리**에 배포하고 JSON을 읽는다. 여백을 제외한 `frame`, 원래 표시 영역의 `sourceSize`, 표시 위치의 `spriteSourceSize`를 함께 사용한다. 사각형은 알파 128 이상인 실루엣에 2px 여백을 더해 계산한다. PNG 픽셀 자체를 잘라내거나 재샘플링하지 않았다.

원본은 모두 1254×1254px이다. 생성 결과의 행·열 간격이 완전히 균등하지 않아 실제 여백에 맞춘 분할선을 사용한다. 원본을 임의로 4등분하지 말고 JSON의 사각형을 사용한다.

캐릭터 프레임은 발바닥 기준으로 배치하며 JSON의 `anchor`를 사용한다. `AnimatedSprite`를 사용할 때 프레임 anchor 적용을 활성화하거나, 같은 anchor를 명시적으로 지정한다. `animations.idle` 등에서 텍스처 순서를 얻는다. `nearest` 샘플링, 비율 유지, 정수 좌표 표시를 우선하고 실제 DPI에서 확인한다.

각 캐릭터는 전면이 보이는 우측 방향을 기본으로 그렸다. 좌우 반전으로 반대 방향을 표현할 수 있다. 상하 방향 전용·뒷모습 그림은 포함하지 않는다. 무기·돌은 캐릭터 그림에 고정하지 않은 독립 레이어다.

## 후속 통합에서 확인할 항목

- 생성된 그림은 저해상도 픽셀풍 래스터 원본이다. 특정 논리 픽셀 격자나 팔레트 제한을 보증하는 수작업 픽셀 원본은 아니다. 실제 표시 크기를 정한 뒤 세부 픽셀 정리가 필요할 수 있다.
- 프레임마다 실루엣·손·머리 위치에 차이가 있으므로 최종 동작 속도와 손잡이 위치는 실제 런타임에서 조정한다. 발 정렬은 atlas에 반영했으며, 무기별 손 소켓은 TBD다.
- 생성 그림에서 몸·머리 폭이 완전히 일정한 것은 아니다. 최종 애니메이션의 부드러움은 게임 통합 후 검토한다.
- 최종 캐릭터 표시 크기·DPI별 가독성·상하 방향 표현 정책·무기 장착 좌표는 TBD다.
- 캐릭터 선택 UI, 스킨 ID 저장과 동기화는 앱 구현 시 연결한다.
- Tauri 투명 창, Windows 바탕화면과 작업 창 위 표시, 서버 판정과의 동기화는 아직 검증하지 않았다.

## 재검사·메타데이터 생성

Windows PowerShell과 기본 .NET `System.Drawing`만 사용하며 JS 패키지나 Rust crate를 설치하지 않는다.

```powershell
& .\packages\game-assets\tools\build-atlases.ps1
node --check packages/game-assets/preview.js
node --check packages/game-assets/preview-data.js
```

생성 스크립트는 PNG를 읽기만 하고 atlas JSON, 미리보기 데이터, 검증 결과를 갱신한다. 16개 셀이 비어 있지 않은지, 투명 배경이 있는지, 알파 128 이상인 픽셀이 셀 경계에서 잘리는지 검사한다. 이 검사는 외형의 완전한 일관성이나 게임 동작 검증을 대신하지 않는다.
