# 게임 코어 · M1 2단계

`@deskbrawl/game-core`는 React·PixiJS·Tauri·NestJS·DB에 의존하지 않는 순수 TypeScript 패키지다. 런타임 의존성은 없으며 개발 도구는 desktop과 동일한 고정 버전을 재사용한다.

## 현재 제공하는 기능

- `WorldState`, `PlayerState`, `PlayerInput`, `ProjectileState`와 월드 크기·게임 규칙 타입.
- `createWorld(setup)`: 명시적인 캐릭터 ID·시작 좌표·월드 크기·규칙으로 tick 0의 월드를 생성한다. 초기 데이터는 복사하며 빈 ID·중복 ID·비정상 수치·월드 밖 충돌 영역을 거절한다.
- `advance(world, inputs)`: 기존 상태나 입력을 수정하지 않고 정확히 한 tick 진행한 다음 상태를 반환한다. 이동은 대각선 정규화와 화면 경계 처리를 포함한다.

## 좌표·시간·입력 규약

- 월드 왼쪽 위가 `(0, 0)`이다. X는 오른쪽, Y는 아래로 증가한다. 위치와 캐릭터 반지름은 월드 논리 단위, 이동 속도는 논리 단위/초다. DPI·모니터 물리 좌표·그림의 발 기준 anchor는 렌더러·네이티브 어댑터에서 변환한다.
- 캐릭터 위치는 원형 충돌 영역의 중심이다. 반지름 전체가 월드 내부에 있도록 제한한다. 캐릭터 간 충돌과 공격 충돌 판정은 아직 없다.
- tick은 0부터 시작한다. `tickMs`, `moveSpeedUnitsPerSecond`, `playerRadius`는 호출자가 지정한다. 제품의 최종 속도·크기·tick 간격은 **TBD**이며 테스트에 사용한 값은 제품 기본값이 아니다.
- `advance`는 실제 시계·난수·타이머·렌더링 프레임을 읽지 않는다. 실시간 스케줄링과 catch-up 상한은 이 함수를 호출하는 로컬/서버 실행 계층에서 담당한다.
- 이동 축은 각각 `-1 | 0 | 1`이다. 키보드와 독립적인 입력 의도이며, 방향키/Z/X를 해석하는 어댑터는 후속 단계에서 연결한다.
- 캐릭터별 입력은 tick마다 한 번만 전달한다. 입력이 누락되거나 두 축이 0이면 정지하고 마지막 바라본 방향을 유지한다. 초기 방향은 기존 에셋과 같은 오른쪽이다. 알 수 없는 캐릭터·중복 입력·허용 범위 밖 축은 `RangeError`로 거절한다.
- 반환된 상태와 내부 데이터는 읽기 전용으로 취급한다. 변경되지 않은 객체는 이전 상태와 공유할 수 있다. 런타임에서 전체 상태를 동결하지는 않는다.

이 타입은 내부 시뮬레이션 모델이다. 네트워크·IPC의 외부 입력을 검증하는 공유 Zod 계약이나 인증·세션·입력 시퀀스 검사를 대신하지 않는다.

## 후속 구현 경계

현재 `projectiles`는 빈 배열로 초기화되며 상태 타입만 정의했다. 근접 공격·투사체 생성/이동/충돌·넉백·기절·면역 처리는 후속 단계에서 추가한다. 앱 렌더러는 두 캐릭터와 상태별 모션을 표시할 수 있으며, 코어 월드 진행·키보드 입력과의 연결은 후속 단계다.

공개 진입점은 `src/index.ts`다. 현재 Vite/Vitest가 TypeScript 소스를 해석하며, 독립적인 JavaScript 배포물이나 Node 서버용 빌드는 아직 만들지 않는다. M2 서버 도입 시 서버 빌드 경계에 맞춘다.

## 검증

저장소 루트에서 실행한다.

```powershell
pnpm test
pnpm check
```

코어만 검사하려면 `pnpm --filter @deskbrawl/game-core test` 또는 `pnpm --filter @deskbrawl/game-core typecheck`를 사용한다. 테스트는 고정 tick을 직접 진행하며 실제 시간 대기나 전역 fake timer를 사용하지 않는다.

2026-10-21 검증: Node 22.20.0, pnpm 10.34.7에서 코어 테스트 56개와 desktop 공개 진입점 연동 테스트 1개 통과. 잘못된 초기값·입력 거절, 8방향 이동 거리, 경계 유지, 입력 해제, 직렬화 후 진행, 1,000 tick 재현성, 초기 상태·입력 불변성을 확인했다. 웹 빌드와 네이티브 실행 검증은 구분하며, 이번 단계의 Tauri·Win32 실기기 검증은 수행하지 않았다.
