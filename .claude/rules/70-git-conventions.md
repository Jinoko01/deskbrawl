# Git·커밋·PR

이 규칙은 브랜치·커밋·이슈·PR 작업 시 적용한다.

- 대상 저장소의 CONTRIBUTING, 커밋 검사, 브랜치 전략, PR 템플릿을 먼저 확인한다.
- 이전 프로젝트의 Jira 키·main/develop 전략·역할 태그·관련 없는 인프라 체크박스를 복사하지 않는다.
- 팀 규칙이 없으면 기존 이력을 따른다. 새 팀 규칙을 임의로 확정하지 않고 미정 사항은 TBD로 남긴다.
- 사용자 변경을 덮어쓰거나 관련 없는 파일을 커밋하지 않는다. 강제 push·히스토리 재작성·브랜치 삭제는 요청 없이 수행하지 않는다.
- PR에는 해결한 문제와 결과, 영향 영역, 계약·DB 변경 여부, 실행한 검증, 남은 제약을 적는다.
- 영향 영역은 실제 변경에 따라 Desktop UI / PixiJS / Tauri·Rust / NestJS / Protocol / PostgreSQL·Prisma / Infra / Docs 중에서 선택한다.
- 프로토콜 변경은 호환성과 배포 순서를, DB 변경은 데이터 이전·잠금 위험·복구 방법을 포함한다.
- commit·push·merge·배포는 요청된 범위에서만 실행한다. 토큰·테스트 인증 파일·환경 비밀값·서명키를 커밋하지 않는다.
