# 풀스택 공통 기본 규칙

- 작업 시작 전에 호출자·상태 소유자·신뢰 경계와 관련 문서를 확인한다.
- `docs/code-quality.md`와 `docs/clean-code-guide.md`의 관련 기준을 적용한다.
- 명세에 없는 기능과 미래 확장용 추상화는 만들지 않는다. 기존 코드·표준 기능·설치된 라이브러리를 먼저 사용한다.
- 서버 판정, 공유 프로토콜, 클라이언트 표현, 네이티브 권한의 책임을 섞지 않는다.
- 기존 디렉토리 구조를 유지하고 이 묶음의 예시 경로는 실제 프로젝트에 맞춘다.
- JS·TS에는 프로젝트 ESLint·TypeScript·포맷 규칙, Rust에는 프로젝트 rustfmt·Clippy 규칙을 적용한다.
- 테스트·생성물·마이그레이션에도 해당 영역의 규칙을 함께 적용한다. 생성 파일을 직접 편집하지 않는다.
- 필요한 외부 스킬이 설치되어 있다고 가정하지 않는다. 특정 플러그인 없이도 규칙을 적용할 수 있어야 한다.
- 문서만 수정한 경우 경로·링크·규칙 미러·내용의 일관성을 확인한다. 앱 코드 검증과 구분해 보고한다.
