# E2E·통합 검증

- `docs/testing-guide.md`를 읽고 웹 UI, 서버 통합, 네이티브 실행 중 무엇을 검증하는지 명시한다.
- Playwright는 Vite에서 제공되는 웹 UI와 브라우저 흐름을 검증한다. IPC mock을 쓴 결과로 Tauri 권한·Win32·설치 파일의 성공을 주장하지 않는다.
- 우선순위는 명세된 핵심 흐름이다. 예를 들어 인증 → 초대 수락 → 방 참여 → 게임 시작·종료를 실제 서버와 연결해 검증하고, 없는 기능을 테스트 때문에 추가하지 않는다.
- 서로 다른 사용자·브라우저 컨텍스트로 여러 클라이언트를 분리한다. 결과는 상대 화면·서버 응답 등 관찰 가능한 동작으로 확인한다.
- DOM은 getByRole·getByLabel·텍스트를 우선하고 CSS class·nth·DOM 계층에 의존하지 않는다. canvas에 그린 요소를 DOM locator로 찾으려 하지 않는다.
- canvas 조작은 테스트 fixture에서 뷰포트·스케일·시드를 고정하고 실제 포인터·키보드 입력을 보낸다. UI 결과나 별도 프로토콜 테스트와 함께 검증한다.
- 임의 sleep 대신 web-first assertion·이벤트·응답을 기다리고, 이벤트 대기는 동작 전에 등록해 수신 경쟁을 피한다. 모든 대기에 timeout을 둔다.
- 각 테스트는 필요한 데이터·방·사용자를 독립적으로 준비하고 정리한다. 다른 테스트의 순서나 고정된 공유 방에 의존하지 않는다.
- 인증 자체를 검사하지 않을 때는 기존 인증 fixture를 재사용한다. storageState는 실제 브라우저 저장 방식에 맞는 경우에만 쓰며 OS 비밀 저장소나 JS 메모리를 복원한다고 가정하지 않는다.
- mock은 장애·타임아웃 등 재현하기 어려운 경계에 제한한다. 실제 서버·DB 검증과 mock UI 테스트 결과를 구분한다.
- Socket.IO 통합 테스트는 인증 거부·방 격리·중복 명령·재연결 후 스냅샷 복구를 위험에 맞게 포함한다.
- 모든 socket·리스너·서버·타이머·DB 연결을 해제한다. 실패 trace·스크린샷·로그에 비밀값이 남지 않게 한다.
- 테스트를 통과시키기 위한 production 전용 우회 분기·임의 지연·강제 클릭·의미 없는 helper를 추가하지 않는다.
