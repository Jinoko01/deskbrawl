# Socket.IO와 Fixed Tick Loop

## 연결·전달

- 소켓의 생성·인증·구독·해제 책임을 정한다. 컴포넌트 렌더마다 연결을 만들거나 재연결 콜백마다 같은 리스너를 중복 등록하지 않는다.
- 소유한 함수 참조로 리스너를 해제한다. 다른 기능의 리스너까지 제거하는 무차별 off를 피한다.
- 연결·재연결·복구 중·실패 상태를 구분하고, 로그아웃·방 이탈·종료 시 연결과 구독을 정리한다.
- Socket.IO는 기본 전달만으로 재연결 후 누락 이벤트 재생이나 exactly-once 실행을 보장하지 않는다. 중요한 명령에는 ack timeout·명령 ID·서버 중복 처리를 설계한다.
- ack의 의미를 수신·수락·틱 적용·영속 완료 중에서 명확히 정한다. timeout은 실패 확정이 아니므로 비멱등 명령을 무작정 재전송하지 않는다.
- 연결이 끊긴 동안의 오래된 이동 입력이 버퍼에서 한꺼번에 실행되지 않도록 폐기·유효 tick·전송 정책을 정한다.
- 재연결 시 다시 인증·인가하고 최신 snapshot과 기준 tick을 받는다. 누락 delta가 있는 상태에 후속 delta만 적용하지 않는다.
- 복구 기능을 사용해도 실패 시 전체 snapshot 경로를 둔다. snapshot 수신 중 도착한 이벤트는 기준 tick·revision으로 순서를 맞춘다.
- room 격리·퇴장·토큰 만료·권한 변경을 서버에서 강제한다. socket.id를 영속 사용자 식별자로 사용하지 않는다.

## 서버 시뮬레이션

- 서버가 이동 허용·충돌·점수·승패를 판정한다. 클라이언트가 보낸 위치·점수·시간을 권위 있는 결과로 사용하지 않는다.
- 클라이언트 입력은 유효성·권한·빈도·sequence·허용 tick 범위를 검사한 뒤 큐에 넣고, 서버 틱 경계에서 정해진 순서로 처리한다.
- 시뮬레이션 step은 고정 dt를 사용한다. 스케줄러의 실제 호출 간격이 정확하다고 가정하지 않고 monotonic clock과 누적 경과 시간으로 보정한다.
- 한 번에 수행할 catch-up step과 입력 큐 크기를 제한하고 과부하 정책을 명시한다. 무한 따라잡기와 겹치는 async tick을 만들지 않는다.
- 틱 주기·방당 인원·보간 지연·전송 주기는 요구와 측정으로 정한다. 정해지지 않은 수치를 임의 목표로 고정하지 않는다.
- simulation step은 가능한 한 순수 함수로 만들고 DB·네트워크·OS 시간·비결정적 난수를 직접 참조하지 않는다. 시간·입력·필요한 seed를 주입한다.
- 렌더 프레임·시뮬레이션 틱·snapshot 전송 주기를 구분한다. 각 단계가 상대 단계의 호출 횟수에 따라 게임 결과를 바꾸지 않게 한다.
- 게임 종료와 결과 영속화의 경계를 정한다. 중복 종료·저장 실패·재시도로 결과가 중복 저장되지 않게 한다.
- 방 종료·서버 종료·테스트 종료 시 루프와 자원을 해제한다. tick 소요 시간·지연·큐 길이를 필요한 수준으로 관찰한다.
- Redis 도입은 다중 프로세스 요구가 생길 때 검토한다. Socket.IO adapter만으로 시뮬레이션 상태·방 소유권·결과 저장이 동기화된다고 가정하지 않는다.
