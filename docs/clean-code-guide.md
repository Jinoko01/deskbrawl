# 클린 코드 가이드

코드를 읽는 사람이 원하는 규칙과 변경 위치를 빨리 찾을 수 있게 작성한다. 프론트엔드의 응집도·단일 책임·추상화 수준 기준을 서버와 Rust에도 적용한다.

## 책임을 나누는 기준

| 경계               | 책임                         | 피할 것                              |
| ------------------ | ---------------------------- | ------------------------------------ |
| React 화면         | 사용자 동작·상태 표시·접근성 | 직접 전송·OS 호출·매 frame 상태 저장 |
| Query 계층         | REST 요청 상태·캐시·무효화   | socket snapshot과 중복 원본 생성     |
| 실시간 어댑터      | 연결·구독·프로토콜 변환      | 클라이언트에서 승패 확정             |
| PixiJS 런타임      | 장면·입력 좌표·보간·자원     | DB 접근·DOM UI 책임 혼합             |
| Rust 어댑터        | OS 기능·권한·자원 수명       | 임의 shell·경로 접근 노출            |
| Controller·Gateway | 전송 경계·컨텍스트 전달      | 핵심 유스케이스 집중                 |
| Service·시뮬레이션 | 인가·상태 전이·게임 규칙     | transport 객체에 종속                |
| Prisma 접근        | 영속 데이터·원자성·조회      | wire DTO로 DB 모델 노출              |
| 공유 프로토콜      | 스키마·DTO·이벤트 계약       | 서버 구현·비밀값·UI 코드             |

표는 책임 구분이며 모든 칸마다 별도 추상 클래스나 패키지를 만들라는 지시가 아니다.

## 응집도와 단일 책임

- 함수 이름에 드러나지 않는 상태 변경을 숨기지 않는다. 여러 단계를 조정하는 유스케이스 함수는 그 목적이 명확하면 허용한다.
- UI의 핵심 제목·동작·성공 후 흐름은 호출부에서 이해할 수 있게 한다. 모든 로직을 불투명한 custom Hook에 넣지 않는다.
- React effect, socket 연결, ticker, Rust handle의 생성과 해제는 같은 소유자가 관리한다.
- 파일 한곳의 짧은 로직은 가까이 둔다. 중복이 적거나 변경 이유가 다르면 공통화보다 독립성을 유지한다.

## 추상화 수준

- 고수준 상태 전이와 raw SQL·FFI·socket emit 세부사항을 한 함수에 뒤섞지 않는다. 실제 변경 경계에만 의미 있는 이름을 붙인다.
- `useRoom()` 안에 인증·연결·렌더링·결과 저장을 모두 감추지 않는다. 필요한 데이터와 동작을 명확히 드러낸다.
- 간단한 map·조건 렌더링은 그대로 읽기 쉬우면 유지한다. JSX 수준을 맞추기 위한 wrapper 컴포넌트를 늘리지 않는다.
- comments는 비자명한 이유·계약·안전 조건에 사용한다. 코드 그대로 읽어주는 주석이나 비활성 코드를 남기지 않는다.

## 검토 질문

- 같은 값을 바꿀 때 여러 저장소를 동기화해야 하는가?
- 명령을 두 번 받거나 연결이 끊겨도 규칙이 유지되는가?
- 창·방·서버가 닫혀도 해제되지 않는 자원이 있는가?
- 해당 변경을 이해하는 데 불필요한 파일·추상화가 많은가?
- 실제 동작을 보장하는 검증이 있으며 구현 세부사항만 검사하고 있지는 않은가?
