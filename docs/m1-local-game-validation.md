# M1 로컬 게임 검증

검증일: 2026-10-21 (Asia/Seoul). M1 구현 순서의 4~8단계(이동·입력 분리, 근접 공격·피격, 돌 던지기, 키 매핑·사용 흐름, 통합 검증)와 WORK/PLAY 전역 전환 단축키를 다룬다.

## 구현 범위

### 4. 이동·입력 분리

- 기존 `main` 창이 로컬 조작 창이다. 투명 오버레이는 포커스와 키보드 입력을 받지 않으며 `local-input` 이벤트로 전달된 명령만 시뮬레이션에 반영한다.
- `local_control`은 `main` 창에서만 호출할 수 있다. Rust가 `kind`·`seq`·이동 축(-1/0/1)·행동(`melee`/`stone`)·`restore`(WORK 전용)와 필드 수를 검사한다. `play`와 `input`은 `main`이 실제 OS 전경 창이고 최소화되지 않았으며 오버레이가 준비·표시된 경우에만 전달한다.
- 게임 키는 PLAY에서만 처리하고 반복 keydown은 무시한다. Ctrl·Alt·Meta와 함께 누른 키는 앱 단축키로 남기고 게임 입력으로 쓰지 않는다.
- Esc, `main` 포커스 상실·최소화, 문서 숨김, 오버레이 숨김·파괴, 시계 지연(5 tick 초과), 조작키 변경에서는 눌린 키를 비우고 WORK로 돌아간다.
- 대각선 이동은 정규화하고 충돌 원이 월드 경계를 넘지 않도록 고정한다. 이동 입력이 없으면 마지막 바라본 방향을 유지한다.

### 전역 전환 단축키

- 전역 등록은 전환 단축키 하나다(기본 `Ctrl+Shift+G`). Win32 `RegisterHotKey`를 `main` HWND에 `MOD_NOREPEAT`로 등록하고, 창 서브클래스가 `WM_HOTKEY`를 받으며 `WM_NCDESTROY`에서 해제한다. 새 crate·JS 패키지는 추가하지 않았다.
- WORK에서 누르면 직전 전경 창을 기억하고 `main`을 복원·전경화한 뒤 `local-play` 이벤트를 보낸다. WebView 포커스가 늦게 도착하면 최대 1초 동안 `focus`를 기다린 뒤 PLAY를 시작한다.
- PLAY에서 다시 누르거나 Esc를 누르면 기억한 작업 창으로 포커스를 돌려준다. 그 창이 사라졌거나 보이지 않으면 `main`을 최소화해 다음 창에 포커스를 넘긴다. 포커스 상실·최소화·리셋으로 인한 WORK 전환에서는 포커스를 옮기지 않는다.
- 트레이 메뉴의 **플레이 시작**은 같은 경로로 PLAY를 시작한다. 단축키를 등록하지 못했을 때의 대안이다.

### 5. 근접 공격·피격

- 근접 공격은 공격자가 바라보는 방향의 앞쪽 반원 안, 중심 거리 `meleeReach + 2 × playerRadius` 이내의 상대에게 적용된다. 재사용 대기 중 입력은 무시한다.
- 피격 시 넉백·기절·피격 면역을 적용한다. 코어가 `knockbackMs ≤ stunMs < invulnerabilityMs`를 강제하므로 넉백은 기절 중에 끝나고, 반복 공격으로 무한 기절이 생기지 않는다.
- 넉백 이동도 월드 경계에서 멈춰 캐릭터가 화면 밖으로 사라지지 않는다. 같은 tick 행동은 피격 적용 전 상태로 수락하고 ID 순서로 처리해 입력 배열 순서에 따라 선공이 정해지지 않는다.

### 6. 돌 던지기

- 돌은 던진 캐릭터의 중심에서 바라보는 방향으로 생성된다. 매 tick 이동 선분으로 충돌을 판정해 빠른 돌도 대상을 통과하지 않으며, 경계 앞의 첫 캐릭터만 맞힌다.
- 캐릭터 적중, 경계 도달, 수명 만료 시 돌을 제거하고 impact/dust 이펙트를 남긴다. 이펙트도 수명이 지나면 제거된다. 피격 처리는 근접 공격과 같은 함수를 사용한다.

로컬 수치(`LOCAL_COMBAT`, 이동 속도, tick 50 ms)는 검증용 조정값이다. 제품 확정값은 TBD다.

### 7. 키 매핑·사용 흐름

- 메인 창의 **조작키 설정**에서 이동 4개·근접 공격·돌 던지기 키와 전환 단축키를 바꾼다. 버튼을 누른 뒤 다음 키를 기록하며 Esc는 기록 취소, Tab은 포커스 이동으로 남긴다. **기본값으로**, **변경 취소**, **저장**을 제공한다.
- 게임 키는 문자·숫자·숫자 패드·방향키·Space만 허용한다. Esc는 플레이 종료 키라서 쓸 수 없고, 같은 키를 두 동작에 쓸 수 없다. 전환 단축키는 Ctrl 또는 Alt를 포함한 수정키 두 개 이상과 문자·숫자·F1~F12 키다. `Ctrl+C`·`Alt+F4` 같은 단일 수정키 앱·OS 단축키와 Win 키 조합은 이 규칙으로 막는다. 화면은 저장 전에 문제를 문장으로 안내하고, Rust가 같은 규칙으로 다시 검증한다.
- 설정 원본은 Rust가 앱 설정 디렉터리의 `controls` 파일에 저장한다. 효과 감소 설정처럼 파일 I/O는 worker에서 수행하고, 단축키 등록은 `main` UI 스레드에서 수행한다. 앱 시작 시 저장된 단축키를 등록하며, 파일이 손상되었으면 기본값을 사용한다.
- 새 단축키를 다른 앱이 이미 쓰고 있으면 `SHORTCUT_IN_USE`로 거부하고 이전 단축키를 다시 등록한다. 파일 저장이 실패해도 이전 단축키로 되돌린다. PLAY 중 또는 설정을 읽는 중에는 저장을 거부한다.
- 시작 시 단축키 등록에 실패하면 메인 창에 경고와 함께 다른 단축키로 바꾸거나 트레이의 **플레이 시작**을 쓰라고 안내한다.
- PLAY 중에는 설정 컨트롤을 비활성화한다. 설정 입력은 WORK에서만 받으므로 키 기록 중 공격이 실행되지 않는다. 메인 창의 상태·조작 안내는 저장된 키와 단축키로 표시한다.
- 효과 감소에서는 판정과 무관한 먼지 이펙트만 숨긴다. 돌·피격 이펙트·기절 표시는 게임 상태라서 정지 자세로 유지하고, 게임 진행은 그대로다.

### 8. 통합 검증 중 수정한 결함

- **PLAY 시작 거부:** 단축키 직후 WebView는 포커스를 받았지만 Tauri의 캐시된 포커스 값이 늦어 `play`가 `MAIN_NOT_FOCUSED`로 거부되는 경우가 있었다. Windows에서는 Rust가 `GetForegroundWindow`와 최소화 여부로 판단한다.
- **PLAY 직후 포커스가 이전 창으로 돌아감:** `main` 활성화 중 포커스가 WebView 자식 창으로 넘어가며 Tauri가 `Focused(false)`를 보낸다. 이 이벤트가 WORK 리셋을 일으키고, WORK 처리가 이전 창으로 포커스를 돌려줬다. 이제 OS 전경 창이 여전히 `main`이면 이 이벤트를 무시하고, 포커스 반환은 Esc의 `restore: true`에서만 한다. 이 결함은 앞선 `Ctrl+Shift+G` 커밋(7d0c300)에도 있었다.

## 실행하지 못한 검증

- `pnpm --config.use-node-version=22.20.0 --filter @deskbrawl/desktop exec node scripts/test-overlay-webview.mjs --local`과 `test-overlay-input.ps1`: 이 PC에 `pwsh`(PowerShell 7)가 없어 실행하지 못했다. 효과 감소의 먼지 숨김은 이 실기기 검사에서 확인하지 않았다.
- 사람이 직접 하는 전체 플레이(근접·돌 적중·기절 복구 체감)와 VS Code·Chrome 위 클릭·키 입력 비방해 재확인은 하지 않았다.
- 관리자 권한 창이 전경일 때의 단축키·포커스 반환, 트레이 **플레이 시작**의 실기기 동작, 설치 파일 생성·설치는 확인하지 않았다.
- 웹 UI 테스트는 Tauri·Win32 실기기 검증을 대신하지 않는다.

## 알려진 제약과 후속 범위

- 기능 명세와 구현 계획의 기본 전환 단축키는 `Ctrl+Shift+F12`다. 사용자 요청에 따라 구현 기본값은 `Ctrl+Shift+G`이며, 명세 문서 갱신은 별도로 결정한다.
- 현재 단축키를 다시 기록하려고 누르면 전역 단축키가 먼저 받아 PLAY 전환이 일어난다. 같은 조합은 저장할 필요가 없어 막지 않았다.
- 레이아웃에 따라 `Ctrl+Alt` 조합이 AltGr 문자 입력과 겹칠 수 있다. 등록은 허용하며 충돌 안내는 하지 않는다.
- 보조 프리셋(Num 8/4/2/6, Num 7/9)은 버튼으로 제공하지 않는다. 숫자 패드 키는 직접 지정할 수 있다.
- 서버·방문 세션의 입력 전송과 FOCUS 모드는 후속 마일스톤 범위다.
