# M1 로컬 게임 검증

검증일: 2026-10-21 (Asia/Seoul). M1 구현 순서의 4~6단계(이동·입력 분리, 근접 공격·피격, 돌 던지기)와 WORK/PLAY 전역 전환 단축키를 다룬다. 7단계(키 매핑·사용 흐름)와 8단계(통합 검증)는 포함하지 않으며 전체 M1 완료를 의미하지 않는다.

## 구현 범위

### 4. 이동·입력 분리

- 기존 `main` 창이 로컬 조작 창이다. 투명 오버레이는 포커스와 키보드 입력을 받지 않으며 `local-input` 이벤트로 전달된 명령만 시뮬레이션에 반영한다.
- `local_control`은 `main` 창에서만 호출할 수 있다. Rust가 `kind`·`seq`·이동 축(-1/0/1)·행동(`melee`/`stone`)과 필드 수를 검사한다. `play`와 `input`은 `main` 포커스와 오버레이 준비·표시 상태를 확인한 뒤에만 전달한다.
- 방향키·Z·X는 PLAY에서만 처리하고 반복 keydown은 무시한다. Esc, `main` 포커스 상실, 문서 숨김, 오버레이 숨김·파괴, 시계 지연(5 tick 초과)에서는 입력을 즉시 해제하고 WORK로 돌아간다.
- 대각선 이동은 정규화하고 충돌 원이 월드 경계를 넘지 않도록 고정한다. 이동 입력이 없으면 마지막 바라본 방향을 유지한다.

### 전역 전환 단축키

- 전역 등록은 `Ctrl+Shift+G` 하나다. Win32 `RegisterHotKey`를 `main` HWND에 등록하고, 창 서브클래스가 `WM_HOTKEY`를 받으며 `WM_NCDESTROY`에서 해제한다. 새 crate·JS 패키지는 추가하지 않았다.
- WORK에서 누르면 직전 전경 창을 기억하고 `main`을 복원·전경화한 뒤 `local-play` 이벤트를 보낸다. WebView 포커스가 늦게 도착하면 최대 1초 동안 `focus`를 기다린 뒤 PLAY를 시작한다.
- PLAY에서 다시 누르거나 Esc를 누르면 기억한 작업 창으로 포커스를 돌려준다. 그 창이 사라졌거나 보이지 않으면 `main`을 최소화해 다음 창에 포커스를 넘긴다. 포커스 상실로 인한 WORK 전환에서는 포커스를 옮기지 않는다.
- 단축키 등록 실패는 앱 시작을 막지 않고 로그만 남긴다. 사용자 안내와 키 변경은 7단계 범위다.
- 메인 창의 "플레이 시작"/"작업 모드로 돌아가기" 버튼은 제거했다. 메인 창은 상태와 조작 안내만 표시한다.

### 5. 근접 공격·피격

- 근접 공격은 공격자가 바라보는 방향의 앞쪽 반원 안, 중심 거리 `meleeReach + 2 × playerRadius` 이내의 상대에게 적용된다. 재사용 대기 중 입력은 무시한다.
- 피격 시 넉백·기절·피격 면역을 적용한다. 코어가 `knockbackMs ≤ stunMs < invulnerabilityMs`를 강제하므로 넉백은 기절 중에 끝나고, 반복 공격으로 무한 기절이 생기지 않는다.
- 넉백 이동도 월드 경계에서 멈춰 캐릭터가 화면 밖으로 사라지지 않는다. 같은 tick 행동은 피격 적용 전 상태로 수락하고 ID 순서로 처리해 입력 배열 순서에 따라 선공이 정해지지 않는다.

### 6. 돌 던지기

- 돌은 던진 캐릭터의 중심에서 바라보는 방향으로 생성된다. 매 tick 이동 선분으로 충돌을 판정해 빠른 돌도 대상을 통과하지 않으며, 경계 앞의 첫 캐릭터만 맞힌다.
- 캐릭터 적중, 경계 도달, 수명 만료 시 돌을 제거하고 impact/dust 이펙트를 남긴다. 이펙트도 수명이 지나면 제거된다. 피격 처리는 근접 공격과 같은 함수를 사용한다.

로컬 수치(`LOCAL_COMBAT`, 이동 속도, tick 50 ms)는 검증용 조정값이다. 제품 확정값은 TBD다.

## 검증 명령과 결과

Windows 11 Enterprise 10.0.26200, pnpm 10.34.7에서 실행했다. JS 검사는 Node v24.14.0으로 실행해 엔진 범위(`>=22.13.0 <23`) 경고가 출력됐다. Node 22.x로 재실행하지 않았다.

| 명령 | 확인 범위 | 결과 |
| --- | --- | --- |
| `pnpm lint` | 두 패키지 ESLint (`--max-warnings 0`) | 통과 |
| `pnpm typecheck` | 두 패키지 strict TypeScript | 통과 |
| `pnpm test` | 코어 70개: 이동·경계·방향·재사용 대기·기절·면역·넉백·돌 충돌·수명·1,000 tick 재현성. desktop 18개: 키 입력 합성·로컬 게임·렌더 모델 | 88개 통과 |
| `cargo fmt --check` | Rust 포맷 | 통과 |
| `cargo clippy --all-targets -- -D warnings` | Rust lint | 통과 |
| `cargo test` | 오버레이 표시 순서·실패 시 숨김·모니터 검증 | 6개 통과 |
| `pnpm tauri build --no-bundle` (`apps/desktop`) | 웹 빌드와 release 실행 파일 | 통과 |

단축키 수정 전에도 같은 lint·typecheck·test·clippy·cargo test가 통과해 4~6단계 기준선을 확인했다.

### 실제 Windows 단축키 확인

release 실행 파일을 띄운 뒤 다른 창(메모장)을 전경에 두고 Windows PowerShell 5.1의 `keybd_event`로 실제 `Ctrl+Shift+G`를 입력했다.

| 단계 | 기대 전경 창 | 결과 |
| --- | --- | --- |
| 단축키 전 | 메모장 | 메모장 |
| 첫 번째 `Ctrl+Shift+G` | DeskBrawl | DeskBrawl |
| 두 번째 `Ctrl+Shift+G` | 직전 작업 창(메모장) | 메모장 |

이 확인은 전경 창 전환만 본다. PLAY 상태 표시, 방향키·Z·X의 오버레이 반영, Esc 복귀는 이 실행에서 관찰하지 않았다.

## 실행하지 못한 검증

- `pnpm --config.use-node-version=22.20.0 --filter @deskbrawl/desktop exec node scripts/test-overlay-webview.mjs --local`: 이 PC에 `pwsh`(PowerShell 7)가 없어 첫 트레이 제어 단계에서 실패했다. 스크립트는 버튼 클릭 대신 실제 `Ctrl+Shift+G`(`overlay-test-control.ps1 -Action play`)로 PLAY에 들어가고, Esc 복귀 뒤 단축키로 PLAY 재진입과 WORK·포커스 반환까지 확인하도록 수정했다. 수정된 검사는 아직 통과 기록이 없다.
- 사람이 직접 하는 전체 플레이(이동·근접·돌·기절 복구)와 VS Code·Chrome 위 입력 비방해 재확인은 하지 않았다.
- `Ctrl+Shift+G`가 다른 앱·IDE 단축키와 충돌하는 경우, 관리자 권한 창이 전경일 때의 포커스 반환, 설치 파일 생성·설치는 확인하지 않았다.
- 웹 UI 테스트는 Tauri·Win32 실기기 검증을 대신하지 않는다.

## 알려진 제약과 후속 범위

- 기능 명세와 구현 계획의 기본 전환 단축키는 `Ctrl+Shift+F12`다. 사용자 요청에 따라 구현은 `Ctrl+Shift+G`이며, 명세 문서 갱신은 별도로 결정한다.
- 단축키 등록 실패를 화면에 알리지 않는다. 트레이 메뉴 전환 대안도 아직 없다.
- 게임 키는 수정키를 구분하지 않아 PLAY 중 `Ctrl+Z`도 근접 공격으로 처리된다.
- 키 매핑 변경·중복 검증·설정 입력 중 공격 차단은 7단계, 전체 통합 검증은 8단계에서 다룬다.
