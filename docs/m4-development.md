# M4 개발 안내

M4의 구현 범위는 호스트 포함 6명, 짧은 단절 후 같은 월드 복구, 캐릭터의 실시간 두 줄 채팅이다. 실제 6대 PC 인수 테스트, 베타 튜닝, 서명·업데이트·운영 배포는 별도 확인이 남아 있다.

## 서버와 앱 갱신

이번 계약은 `packages/protocol`의 **version 2**다. 2인용 version 1 앱과 서버를 섞어 실행하지 않는다. 서버와 모든 참가자의 앱을 함께 갱신한다.

기존 개발 DB에는 다음 migration을 적용한다. `20261022000000_m4_six_participants`는 `HostRoom.maxParticipants` 기본값을 6으로 바꾸고 기존 값 2를 6으로 갱신하며, 사용자·초대·기기 데이터를 지우지 않는다. 운영 DB의 migration과 배포는 대상을 검토하고 승인받아 실행한다.

```powershell
pnpm --filter @deskbrawl/server build
pnpm --filter @deskbrawl/server exec node --env-file=.env node_modules/prisma/build/index.js migrate deploy
pnpm dev:server
```

Node 22와 manifest의 pnpm 10을 사용한다. 동일 Wi-Fi의 다른 PC에는 [LAN 설정 안내](m2-development.md)에 따라 서버 PC의 실제 LAN IP로 생성한 앱을 설치한다. `localhost`는 각 PC 자신을 뜻한다. 서버 IP가 바뀌면 `network:config`를 다시 실행해 CSP와 Vite 주소를 함께 갱신하고 앱을 재빌드한다.

## 6인 공간과 복구

- 정원은 호스트 1명 + 방문자 5명이다. 7번째 입장은 `ROOM_FULL`로 거부한다.
- 각 캐릭터의 닉네임과 번호로 참가자를 구분한다. 이동·공격 판정은 계속 서버가 결정한다.
- 단절 즉시 눌린 키·대기 공격·채팅을 폐기하고 PLAY를 멈춘다. 마지막 월드는 화면에 유지한다.
- Socket.IO의 제한된 재접속과 서버의 10초 유예 안에서 JWT와 회전 복구 토큰이 유효하면 같은 캐릭터·월드로 돌아온다. 전체 스냅샷을 받고 입력 seq를 새로 시작한다. 과거 공격·초안을 재전송하지 않는다.
- 복구 실패·호스트 종료·강퇴 시 안내하고 로컬 캐릭터를 복원한다. 재입장은 사용자가 다시 선택한다.
- 귀환·방 이동·집중·정상 앱 종료는 명시적인 퇴장으로 처리한다. X·종료 버튼·트레이 종료는 서버 알림을 잠시 기다리되 1.25초 뒤 네이티브 종료를 보장한다. 네트워크가 끊긴 상태라면 서버의 유예 만료로 정리된다.

10초 유예와 재시도 횟수는 이번 구현값이며 실기기 베타 튜닝은 남아 있다. 서버 프로세스를 재시작하면 메모리 월드는 복구되지 않는다.

## `/` 채팅

서버 공간에 연결하고 PLAY에서 `/`를 누른다. 홈 창은 복원하지 않고 캐릭터 근처에 작은 입력창을 연다. 채팅 중에는 이동·공격 키를 캡처하지 않으며, 닫은 뒤 WORK가 된다. 플레이하려면 모드 전환 단축키를 다시 누른다. WORK에서 `/`는 작업 앱에 그대로 전달된다.

입력 중인 내용은 같은 공간에 즉시 공유된다. **Enter는 전송 버튼이 아니라 현재 줄을 이전 줄로 옮기고 계속 입력하는 키**다. 현재 줄과 이전 줄을 각 50 UTF-16 단위까지 표시한다. Escape·다른 창 클릭·모드/공간 전환은 말풍선을 지운다. 입력을 멈추면 5초 후 흐려지고 8초 후 닫힌다. 한글 조합 중 Enter·Escape는 조합 처리를 우선한다.

채팅은 서버 메모리의 최신 두 줄만 유지하고 DB에 기록하지 않는다. 전송은 50ms마다 최신 초안을 합쳐 보내고 서버는 참가자별 순서·빈도·길이를 검증한다. 이 전송 주기와 Tauri 입력창은 DeskBrawl의 설계다. Figma에서 확인한 정적 코드 근거와 확인하지 못한 부분은 [REA 조사 기록](m4-figma-chat-research.md)에 구분했다.

검증 범위·남은 작업은 [M4 검증 기록](m4-validation.md), 서버 실측은 [6연결 측정](m4-server-measurements.md), Docker·서명 준비는 [배포 안내](m4-deployment.md)를 따른다.
